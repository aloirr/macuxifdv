# T-0039 — Checkout validado na API

## Onde
**Local** (R-20261101-165024, item B). Começa depois do merge do PR #27 (T-0037).

## Objetivo
A API passa a validar o checkout da visita, reaproveitando `prepararCheckoutVisita` do domain do Core (PR #27):
- o motivo de "sem pedido" tem de estar na lista do tenant;
- as etapas obrigatórias do checkout, inclusive as de outros módulos (pelo contrato), têm de estar cumpridas.
Um aparelho antigo ou adulterado não conclui visita fora da RN-CORE-12.

## Critérios de aceite
- [ ] Checkout com motivo fora da lista do tenant é recusado (422), com teste
- [ ] Checkout sem uma etapa obrigatória (do Core ou de outro módulo, pelo contrato) é recusado, com teste
- [ ] Push do aparelho com checkout inválido não grava a visita como concluída; o erro volta ao app
- [ ] Multi-tenant e permissões cobertos; nenhum teste com hora fixa contra o relógio real
- [ ] Lint, typecheck e testes verdes; revisão sem 🔴

## Ordem e agentes
1. engenheiro-software: desenho (contrato das etapas de outros módulos)
2. modulo-core: implementação na API do Core
3. testes: validação
4. engenheiro-software: revisão; gerente: fechamento
