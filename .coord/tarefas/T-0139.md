# T-0139 — Recados online (sem depender do Cowork)

## Origem
Decisão do dono do produto no chat de 08/11/2026, por volta das 13h25. O texto literal está no recado R-20261108-132842-gerente-projetos. A tarefa entra na esteira sem esperar o build.

## Objetivo
Os recados passam a ficar online, num repositório privado próprio, `macuxifdv-recados`.

**Repositório:**
- Mesma estrutura de hoje: `recados/<destino>/R-*.md` e `lidos/<agente>.txt`.
- O histórico atual de `.coord/recados` e `.coord/lidos` é migrado para lá.
- O `.gitattributes` traz `lidos/*.txt merge=union`.

**No PC:**
- `C:\macuxifdv\.coord\recados` e `.coord\lidos` viram junções (`mklink /J`) para o clone `C:\macuxifdv-recados`.
- As duas pastas entram no `.gitignore` do repositório de código, e a remoção delas fica registrada em commit.
- O guardião e os scripts continuam funcionando sem mudança de caminho.

**Sincronização:** o script `scripts/sincronizar-recados.ps1` faz `git pull --rebase`, depois add, commit `recados: sync <host> <hora>` e push. Ele roda a cada 2 min pelo Agendador de Tarefas e também no início e no fim de cada sessão, por hook. Não trava, não apaga recado e não grava segredo.

**Actions no repositório de recados:**
- `issue-recado.yml`: o formulário de issue "Recado" vira um arquivo de recado do dono do produto e a issue é fechada. Só vale para issue aberta pela conta domontecristo.
- `aviso-telegram.yml`: manda um aviso no Telegram quando chega recado na caixa do dono do produto.
- `status-horario.yml`: manda um resumo de hora em hora, só quando há novidade.

## Critérios de aceite
1. Um recado criado pelo formulário no celular chega à caixa do destino no PC em até 3 min.
2. Um recado do gerente para o dono do produto chega ao Telegram em até 3 min.
3. Dois agentes marcando `lidos` ao mesmo tempo não geram conflito.
4. Nenhum segredo nos arquivos, e o repositório é privado.
5. Há um passo a passo para o dono do produto:
   - criar o repositório;
   - criar o bot no Telegram (BotFather);
   - pegar o chat id;
   - cadastrar os 2 secrets (`TELEGRAM_BOT_TOKEN` e `TELEGRAM_CHAT_ID`).
6. ADR escrita pelo engenheiro-software; doc 07 (§ recados) e CLAUDE.md atualizados pelo gerente.
7. **Pronto quando:** houver um recado na caixa do dono do produto com o sha, a ADR, os links das Actions e o passo a passo dos secrets.

## Ordem e agentes
1. **engenheiro-software:**
   - a ADR;
   - o `.ps1`, com teste do que der para testar;
   - os 3 workflows e o formulário de issue, preparados numa pasta do caminho dele para irem ao repositório novo;
   - o script de migração e de corte das junções, para o dono do produto rodar com os agentes parados;
   - os diffs de governança (`.gitignore`, se não for dele, e o hook de sessão);
   - a conferência de que o guardião e o `coord.mjs` funcionam através das junções.
2. **Dono do produto:** cria o repositório e os secrets, roda o corte e cadastra a tarefa no Agendador. O gerente manda o passo a passo.
3. **gerente-projetos:**
   - doc 07 e CLAUDE.md;
   - aplicar os diffs de governança com o ok do dono do produto;
   - verificar ponta a ponta.
4. **testes:** confere os critérios 1 a 3.

## Premissas
- O repositório `aloirr/macuxifdv-recados` é criado pelo dono do produto, seguindo o passo a passo. Os agentes não criam repositório.
- O corte das junções só é feito com todos os agentes parados, porque um recado escrito durante a mudança pode se perder.
