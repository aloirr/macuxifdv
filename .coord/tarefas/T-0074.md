# T-0074 — Ambiente demo/homologação na Magalu Cloud

## Onde
**Local** (o preparo da VM usa SSH a partir deste PC). O CI/CD roda no GitHub Actions.

**Decisão do dono do produto (04/11, versão 2, substitui a de 03/11 23h):**
- a demo e a homologação ficam na Magalu Cloud, **sempre ligadas**;
- o PC dele fica só com desenvolvimento (VS Code, Claude Code, `pnpm dev`, Postgres de testes no Docker);
- **domínio definitivo: `macuxifdv.com.br`**.

> ⚠️ **Urgente.** O túnel antigo `macuxi-demo` (PC) está parado e sem DNS, e as rotas `api-demo`/`bko-demo` já apontam para o túnel novo. Até o primeiro deploy verde na VM, **a demo não responde pelo domínio**. Por isso esta tarefa entra na frente das vagas livres do engenheiro-software.

Nenhum agente acessa as contas da Magalu nem da Cloudflare. Segredos ficam só nos secrets.

  - br-se1-a, Ubuntu 24.04 LTS, BV2-8-40 (2 vCPU, 8 GB, 40 GB);
  - IPv4 177.93.129.233, usuário `ubuntu`;
  - chave SSH **`macuxi-deploy-v2`**, com a privada em `%USERPROFILE%\.ssh\macuxi-deploy-v2`; use-a só com `ssh -i`, sem ler, copiar nem exibir o conteúdo;
  - grupo de segurança com entrada só TCP 22.
- **Object Storage:** bucket privado `macuxi-demo-arquivos` (br-se1).
  - API Key **`macuxi-demo-s3`**, válida de 04/11/2026 a 31/12/2026, conforme o print do painel enviado pelo dono do produto em 04/11.
  - É a chave ativa. A anterior, de mesmo nome, foi revogada pelo dono do produto em 04/11.
  - Renovar antes de 31/12/2026; o gerente avisa o dono do produto em 15/12 (backlog).
- **Cloudflare:** túnel **`macuxi-demo-nuvem`**, gerenciado pelo painel e conectado por token. Rotas:
  - `api-demo.macuxifdv.com.br` → `http://api:8100`;
  - `bko-demo.macuxifdv.com.br` → `http://bko:3100`.
- **GitHub Environment chamado `DEMO_SSH_KEY`.** Atenção: esse é o NOME DO ENVIRONMENT, então os workflows usam `environment: DEMO_SSH_KEY`. Todos estes são **secrets** dentro dele:
  - `DEMO_SSH_KEY` e `DEMO_S3_KEY_ID`;
  - `DEMO_S3_SECRET` e `DEMO_CLOUDFLARE_TUNNEL_TOKEN`;
  - `DEMO_HOST` e `DEMO_USER` (estão como secrets, não como variables).

## Objetivo
1. **ADR "Ambiente demo/homologação na Magalu Cloud"**, como **proposta para aprovação do dono do produto**, e preparo da VM:
   - Docker + Compose;
   - SSH só por chave, sem senha e sem root;
   - fail2ban;
   - atualizações de segurança automáticas;
   - fuso UTC.
   O preparo fica num script idempotente no repositório.
2. **Compose na VM** com estes serviços:
   - `api` (8100), `worker` e `bko` (3100);
   - `postgres` (`pgvector/pgvector:pg16`, a mesma imagem do CI), com a porta só na rede interna;
   - `cloudflared`, com `TUNNEL_TOKEN` vindo de `DEMO_CLOUDFLARE_TUNNEL_TOKEN`.
   **Os nomes `api` e `bko` precisam bater com as rotas do túnel.**
3. **CI/CD:**
   - imagens montadas no GitHub Actions e publicadas no GHCR;
   - deploy no merge do `main` (migrações + `compose up` + `docker image prune`) com `environment: DEMO_SSH_KEY`;
   - workflow manual "recriar base demo" (`seed demo --recriar`).
4. **Complemento da ADR 0010:**
   - adaptador S3 genérico da porta `ArmazenamentoArquivos`, com endpoint, região, bucket e chave por variável, apontando para o Object Storage da Magalu (br-se1);
   - o disco local continua em dev e no CI.
5. **Backup:** `pg_dump` diário para o bucket (`backups/`, 7 dias de retenção), com restauração testada.
6. **Docs:**
   - `docs/status/demo.md` (gerente) e `scripts/demo/LEIA-ME.md` (engenheiro-software) atualizados;
   - `subir-demo`/`derrubar-demo` viram plano B local, **só com túnel rápido**;
   - **`configurar-dominio.ps1` NÃO deve mais ser usado**, porque sobrescreveria o DNS do servidor. Ele fica bloqueado ou com aviso, e ninguém o roda;
   - o Postgres local do PC passa a ser só o de testes.
7. **Sem build nova de APK só por isso:** os APKs de preview atuais já apontam para `api-demo`.

## Critérios de aceite
1. Com o PC do dono do produto desligado, `https://api-demo.macuxifdv.com.br/v1/saude` e `https://bko-demo.macuxifdv.com.br/login` respondem. O túnel `macuxi-demo-nuvem` aparece **Healthy** com origem 177.93.129.233 (o dono do produto confere no painel).
2. O APK de preview faz login, pedido, aprovação e foto, e a foto aparece no BKO vinda do bucket.
3. O merge no `main` publica sozinho, o workflow manual recria a base e o backup diário aparece no bucket, com restauração testada.
4. Um teste prova que um tenant não lê foto de outro (RN-CORE-05), com o adaptador S3 (MinIO no CI).
5. Nenhum segredo no repositório: JWT e senhas dos papéis são gerados na VM (`/opt/macuxi/.env`, modo 600). O resto vem dos secrets.
6. VM endurecida: só chave, root e senha desligados, fail2ban, `unattended-upgrades` e UTC.
7. ADRs, quadro, diário e docs atualizados. Lint, typecheck e testes verdes.
