> R-20261102-093007 · regras: RN-VEN-02/03/10/11/15/16/17, RN-INT-08 · decisão de compatibilidade: [ADR 0016](../decisoes/0016-pedido-ao-erp-ampliado-no-v1.md)

## 1. Premissas do gerente — confirmadas
| Premissa | Decisão |
|---|---|
| Árvore em `catalogo` (`catalogo_no`, `produto_no`) | **Confirmada.** É navegação de catálogo (RF-CAT-04); o Core não precisa dela |
| `produto_unidade` e `cliente_endereco` em `core` | **Confirmada.** Cadastro base (ADR 0005); o Vendedor lê pela consulta do Core (§4.3), nunca pela tabela |
| `transportadora` (e `cliente_frete`) em `vendedor` | **Confirmada.** Só o pedido usa; o BKO de transportadoras é do Vendedor |
| RN-VEN-11 (preço mínimo) por item | Confirmada; `pedido_item.preco_minimo_cents` (0013) é o retrato |

## 2. Três regras de modelagem (valem para todos os contratos abaixo)
1. **Quantidade fora do Vendedor é sempre na UNIDADE BASE.** O Vendedor guarda a quantidade na unidade vendida + `fator` +
   `quantidade_base` (0013). Em tudo que sai dele — evento `vendedor.pedido.aprovado@1`, `PedidoParaErp`, `ItemFaturado` do
   retorno, metas — `quantidade` = unidade base, e a unidade vendida vai em campos novos (`unidade`, `fator`,
   `quantidade_venda`). Assim o Conector 1.2.x, que não conhece unidade, grava no ERP uma quantidade **certa** (ADR 0016).
   Consequência no banco: `pedido_item.quantidade_faturada` deve ser **na unidade base** (o ERP fatura 6 UN de uma "CX c/ 12"):
   check `quantidade_faturada between 0 and quantidade_base` (pedido ao banco-dados, §6).
2. **Percentuais seguem como hoje** (`Pct`, número 0–100 com 2 casas, `numeric(5,2)`).
   Dinheiro sempre em centavos inteiros; arredondamento meia para cima **por item** (RN-VEN-02), na unidade vendida.
3. **Desconto OU acréscimo**, nunca os dois, no item e no pedido (check do banco + `superRefine` no contrato + domain).

## 3. Preço (domain do Vendedor, T-0053) — assinatura combinada
```ts
// modules/vendedor/domain/preco-pedido.ts (testes antes; os casos do §5 da T-0061)
export interface ItemParaPreco { preco_tabela_unidade_cents: number; quantidade: number; fator: number;
  preco_proprio_unidade_cents?: number | null; desconto_pct: number; acrescimo_pct: number }
export function precoDoItem(i: ItemParaPreco): { preco_tabela_cents: number; preco_unitario_cents: number; total_cents: number;
  quantidade_base: number }                                  // preço da CX = UN × fator, salvo preço próprio (RN-VEN-15)
export function totaisDoPedido(itens, pedido: { desconto_pct: number; acrescimo_pct: number },
  frete: { tipo: 'valor' | 'percentual'; valor_cents?: number; pct?: number } | null):
  { total_tabela_cents; total_itens_cents; desconto_cents; acrescimo_cents; total_cents; frete_cents; total_a_pagar_cents;
    desconto_efetivo_pct }                                   // RN-VEN-03: sem frete; negativo = acréscimo
export function nivelDeAprovacao(desconto_efetivo_pct, alcadas): NivelAprovacao | null   // RN-VEN-10: só o efetivo; ≤ 0 nunca
```
`total_cents` do pedido continua **sem o frete** (base da alçada e da meta, RN-CORE-21; igual à 0013); `total_a_pagar_cents` =
`total_cents + frete_cents`. Frete percentual incide sobre `total_cents`.

## 4. Contratos (o dono de cada pasta escreve; texto exato)

### 4.1 Core (modulo-core) — `modules/core/contracts`
```ts
// sync.ts — entidades novas do pull
export const ProdutoUnidadeSyncSchema = z.object({ ...Base, produto_id: z.string().uuid(),
  unidade: z.string(), fator: z.number().int().positive(), ean: z.string().nullable(), padrao: z.boolean(), ativo: z.boolean() }).strict();
export const ClienteEnderecoSyncSchema = z.object({ ...Base, cliente_id: z.string().uuid(),
  tipo: z.enum(['principal', 'entrega', 'cobranca']), descricao: z.string().nullable(),
  logradouro: z.string(), numero: z.string().nullable(), complemento: z.string().nullable(), bairro: z.string().nullable(),
  cidade: z.string(), uf: z.string(), cep: z.string().nullable(),
  latitude: z.union([z.string(), z.number()]).nullable(), longitude: z.union([z.string(), z.number()]).nullable(),
  principal: z.boolean(), ativo: z.boolean() }).strict();
```
- Provedores: `produto_unidade` (escopo tenant, sem janela), `cliente_endereco` (escopo carteira, `colunaCliente: 'cliente_id'`).
  `ProdutoSyncSchema` **não** ganha `custo_cents` (dado interno, 0013).
- `core.cadastro_resumo@1` (consultas.ts) — entrada ganha `endereco_ids: Ids` (opcional, padrão `[]`); saída ganha, opcionais:
  `produtos[].unidades: z.array(z.object({ unidade: z.string(), fator: z.number().int().positive(), padrao: z.boolean(),
  ativo: z.boolean(), external_id: Texto })).optional()` e `enderecos: z.array(z.object({ id, cliente_id, tipo, logradouro,
  numero, complemento, bairro, cidade, uf, cep, principal, ativo, external_id })).optional()` (só os pedidos em `endereco_ids`
  e, sempre, o principal de cada cliente pedido). Mesma versão: só campos opcionais (ADR 0012).

### 4.3 Vendedor (modulo-vendedor) — `modules/vendedor/contracts`
```ts
const Frete = z.object({
  modalidade: z.enum(['CIF', 'FOB']),
  tipo: z.enum(['valor', 'percentual']).nullable().optional(),
  valor_cents: z.number().int().nonnegative().nullable().optional(),
  pct: Pct.min(0).max(100).nullable().optional(),
  transportadora_id: Id.nullable().optional(),                 // da lista (vendedor.transportadora)
  transportadora_digitada: z.object({ nome: z.string().trim().min(2).max(120),
    documento: z.string().regex(/^\d{14}$/).nullable().optional(), telefone: z.string().max(30).nullable().optional() })
    .nullable().optional(),
}).superRefine(/* CIF: sem transportadora; FOB: id XOR digitada; tipo 'percentual' exige pct, 'valor' exige valor_cents */);

const ItemPush = z.object({ product_id: Id, quantity: z.number().int().positive(),
  unidade: z.string().regex(/^[A-Z0-9]{1,6}$/).optional(),     // ausente = unidade padrão do produto (APK antigo = base)
  desconto_pct: Pct.min(0).max(100).optional(), acrescimo_pct: Pct.min(0).max(100).optional() });

export const PedidoPush = CreateOrderRequest.extend({
  items: z.array(ItemPush).min(1).max(200),
  // … campos atuais …
  tipo: z.enum(['pedido', 'orcamento']).optional(),            // ausente = 'pedido' (APK antigo)
  acrescimo_pct: Pct.min(0).max(100).optional(),
  frete: Frete.nullable().optional(),                          // ausente = padrão do cliente/tenant (RN-VEN-16)
  endereco_entrega_id: Id.nullable().optional(),               // ausente = principal (RN-VEN-17)
});
```
- O `fator` **não** vem do aparelho: a API lê da `core.cadastro_resumo@1` (`produtos[].unidades`) e recusa unidade inexistente
  (código novo em `CODIGOS_RECUSA_PEDIDO`: `unidade_invalida`). Endereço que não é do cliente → `endereco_invalido`.
  Transportadora digitada com `frete.transportadora_digitada = false` no parâmetro → `transportadora_digitada_proibida`.
- `PedidoSyncSchema` ganha, opcionais: `tipo`, `orcamento_validade`, `orcamento_id`, `convertido_em`, `acrescimo_pct`,
  `desconto_efetivo_pct`, `frete_modalidade`, `frete_tipo`, `frete_pct`, `frete_cents`, `transportadora_id`,
  `transportadora_digitada`, `transportadora_nome`, `transportadora_documento`, `transportadora_telefone`,
  `endereco_entrega_id`, `endereco_entrega: EnderecoRetrato.nullable().optional()`, `enviado_erp_em`, `integrado_em`,
  `faturado_em`, `total_faturado_cents`. `PedidoItemSyncSchema`: `fator`, `quantidade_base`, `acrescimo_pct`,
  `preco_minimo_cents`, `quantidade_faturada` (todos `.optional()`).
- Entidades novas do pull: `TransportadoraSyncSchema { ...Base, nome, documento: nullable, inscricao_estadual: nullable,
  telefone: nullable, ativo }` (tenant) e `ClienteFreteSyncSchema { ...Base, cliente_id, modalidade: 'CIF'|'FOB',
  transportadora_id: nullable }` (carteira).
- `OrderDetail`/`OrderItem` (BKO e PDFs), opcionais: item `unit`, `factor`, `base_quantity`, `surcharge_pct`; pedido
  `surcharge_pct`, `effective_discount_pct`, `freight: { modality, type, pct, cents, carrier_name, carrier_document,
  carrier_phone, carrier_typed }`, `delivery_address: EnderecoRetrato`, `total_to_pay_cents`.
- Parâmetros (plataforma.parametro, módulo `vendedor`): **`frete.modalidade_padrao`** (`'CIF' | 'FOB'`, padrão CIF; doc 03
  `frete_modalidade_padrao`) e **`frete.transportadora_digitada`** (boolean, padrão true; doc 03 `frete_transportadora_digitada`).
- **`vendedor.pedido.aprovado@1`** (eventos.ts), aditivo (o Hub é o único consumidor; nenhum campo muda de sentido):
```ts
itens[]: + unidade: z.string().nullable().optional(), fator: z.number().int().positive().optional(),
           quantidade_venda: z.number().int().positive().optional(), preco_tabela_cents: CentsNaoNeg.optional(),
           desconto_pct: Pct.optional(), acrescimo_pct: Pct.optional(), acrescimo_cents: CentsNaoNeg.optional()
           // `quantidade` passa a ser documentada como UNIDADE BASE (hoje toda venda é UN: mesmo valor)
+ desconto_pct, acrescimo_pct: Pct.optional(), acrescimo_total_cents: CentsNaoNeg.optional(),
+ frete: FreteErp.nullable().optional(), endereco_entrega: EnderecoErp.nullable().optional(),
+ total_a_pagar_cents: CentsNaoNeg.optional()
```
  (`FreteErp` e `EnderecoErp` com o mesmo formato do §4.4; o Vendedor resolve `transportadora_external_id` e o `external_id` do
  endereço no aceite.) **Orçamento nunca publica `aprovado@1`** (não vai ao ERP).

### 4.4 Integração (modulo-integracao) — `modules/integracao/contracts` (detalhe e compatibilidade na ADR 0016)
**Entidades canônicas novas** (ERP → Macuxi; uma view por entidade, como as atuais; `ENTIDADES` passa de 8 para 12, aditivo no v1):
```ts
export const CatalogoNoPayload = RegistroBase.extend({ codigo: Texto(60), nome: Texto(120),
  pai_external_id: ExternalId.nullish(), nivel: z.number().int().min(1).max(8), ordem: z.number().int().default(0) });
export const ProdutoUnidadePayload = RegistroBase.extend({ produto_external_id: ExternalId,
  unidade: z.string().trim().toUpperCase().regex(/^[A-Z0-9]{1,6}$/), fator: z.number().int().positive(),
  ean: z.string().trim().regex(/^\d{8}$|^\d{12,14}$/).nullish(), padrao: z.boolean().default(false) });
export const ClienteEnderecoPayload = RegistroBase.extend({ cliente_external_id: ExternalId,
  tipo: z.enum(['principal', 'entrega', 'cobranca']).default('entrega'), descricao: TextoOpcional(80),
  ...Endereco.shape /* logradouro e cidade e uf obrigatórios aqui */, principal: z.boolean().default(false),
  latitude: z.number().min(-90).max(90).nullish(), longitude: z.number().min(-180).max(180).nullish() });
export const TransportadoraPayload = RegistroBase.extend({ nome: Texto(120),
  documento: z.string().trim().regex(/^\d{14}$/).nullish(), inscricao_estadual: TextoOpcional(20), telefone: TextoOpcional(30) });
```
- `ProdutoPayload` ganha `catalogo_no_external_id: ExternalId.nullish()` (produto → nó; referência **fraca**: nó ausente vira
  aviso `referencia_fraca_ausente` e o produto entra sem nó). `PrecoPayload` ganha `unidade: TextoOpcional(6)` (fila de corte).
  `ClientePayload`: `inscricao_estadual`, `observacao` (T-0060).
- `CAMPO_SOMA_CONTROLE`: as 4 novas = `null` (só contagem). Ordem de aplicação (A7): `catalogo_no` antes de `produto`;
  `produto_unidade` depois de `produto` e `cliente_endereco` depois de `cliente` (referência forte: ausente = `referencia_ausente`,
  reprocessável, como `titulo → cliente`); `transportadora` sem dependência.
- Eventos do Hub para os donos: `integracao.catalogo_no.atualizado@1` (catálogo), `integracao.produto_unidade.atualizado@1` e
  `integracao.cliente_endereco.atualizado@1` (core), `integracao.transportadora.atualizado@1` (vendedor, **fila de corte**).
  Registrar em `.coord/contratos/eventos.md` (eu registro quando o modulo-integracao confirmar os nomes).
- **`PedidoParaErp` / `ItemPedidoErp`**: campos opcionais da ADR 0016 §Decisão 2 (unidade/fator/quantidade_venda,
  descontos e acréscimos, `frete`, `endereco_entrega`, `total_a_pagar_cents`) + `exige_conector` calculado no domain.
- `ItemFaturado.quantidade` documentada como **unidade base** (sem mudança de formato).

## 5. Pull do app (motor do platform-sdk, T-0059)
Entidades novas: `core.produto_unidade`, `core.cliente_endereco`, `catalogo.catalogo_no`, `catalogo.produto_no`,
`vendedor.transportadora`, `vendedor.cliente_frete`. Todas `pull`/`servidor_vence`, com o cursor por entidade e página que a

## 6. Pedidos aos donos (recados com os nomes finais)
- **banco-dados**: (a) `pedido_item.quantidade_faturada` na unidade base (`between 0 and quantidade_base`, §2.1); (b) check de

  (versão mínima do Conector para o pedido, ADR 0016); (d) base demo: árvore de 3 níveis, produtos com UN e CX, 2 endereços
  em alguns clientes, 2 transportadoras (já pedido pelo gerente).
- **modulo-core**: §4.1 + T-0060; provedores de sync; aplicar `integracao.produto_unidade/cliente_endereco.atualizado@1`.

  (o evento `integracao.produto.atualizado@1` passa a ter o campo; o Catálogo passa a consumi-lo **só** para `produto_no`).
- **modulo-vendedor** (T-0053): §3 e §4.3.
- **modulo-integracao**: §4.4 e a ADR 0016.
- **engenheiro-apps**: componentes das abas e do rodapé em `packages/ui`; nada de contrato.
