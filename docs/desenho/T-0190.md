## 2. Armazenamento e publicação
- Bucket privado da produção (`macuxi-prod`), prefixo `pacotes/`. Cada variante tem a sua pasta:
  - `pacotes/campo/<Campo-Oficial-vX.Y.Z.apk>` e `pacotes/campo/ultimo.json`;
  - `pacotes/gestao/<Gestao-Oficial-vX.Y.Z.apk>` e `pacotes/gestao/ultimo.json`.

  O manifesto segue o `PacotePublicadoSchema`, sem mudança: versão, arquivo, tamanho, sha256 e data.
- CLI: `pnpm --filter api publicar-pacote campo|gestao <apk> --versao X.Y.Z`. Grava o APK como `application/vnd.android.package-archive` e só depois o `ultimo.json`.
- Workflow `apk-publicar.yml`, só manual, no environment `PRODUCAO`. Entradas: `run_id` (a execução do `android-build.yml`), `variante` (`campo`, `gestao` ou `ambas`), `versao` e `simular`.
  - Baixa o artefato `<Campo|Gestao>-Oficial-vX.Y.Z` daquela execução e confere se o `.apk` existe.
  - Roda a CLI com `PROD_S3_KEY_ID`/`PROD_S3_SECRET`. O `android-build.yml` não muda.

## 3. Porta no SDK (o que o Core usa)
- `PRODUTOS_PACOTE = ['conector', ...VARIANTES_APP]`. Assim, `ProdutoPacote` aceita `'campo' | 'gestao'` e toda `VarianteApp` é um `ProdutoPacote`.
- A rota do Core recebe a porta em `ctx.pacotes`, que a API preenche em toda rota de módulo; nada muda no bootstrap:
  - `ctx.pacotes.linkDoUltimo(variante)` devolve `LinkPacote | null`: `versao`, `arquivo`, `tamanho_bytes?`, `sha256?`, `publicado_em?`, `url` e `expira_em`;
  - `null` quer dizer que não há APK publicado: a rota responde 404 `APP_SEM_PACOTE`;
  - sem S3, com bucket fora ou manifesto inválido, a porta lança `ErroHttpModulo` 503 `ARMAZENAMENTO_INDISPONIVEL`;
  - se `ctx.pacotes` vier ausente (contexto de teste antigo), responda o mesmo 503, como faz o `conector-download.ts`.
- Teste de módulo: `criarServicoPacotesMemoria({ campo: { versao: '1.0.19', arquivo: 'Campo-Oficial-v1.0.19.apk' } })`.

## 4. Rota do Core (modulo-core)
- `POST /v1/core/apps/download`, corpo `{ variante: 'campo' | 'gestao' }`, validado por Zod com `VARIANTES_APP` do SDK. Ação `app.baixar`, perfil admin (o super-admin entra pelo portal). Carteira: `nao_se_aplica`.
- Licença no `domain` do Core, função pura com teste citando RN-CORE-67: a variante só sai se o tenant tem licença de algum módulo que usa aquele app. Sem licença, 403 `APP_SEM_LICENCA`.
- Resposta: `LinkPacoteSchema.extend({ variante })`, com o `LinkPacoteSchema` do SDK (o mesmo que o contrato do Conector deve usar).
- Auditoria `core.app_download_link`, gravada dentro da transação antes de responder, com `{ variante, versao, arquivo }`. Nunca leva a `url`.

## 5. Rota pública de versão
Dois contratos (o novo, `contrato=2`, sem `apk_url`; o antigo para os apps v1.0.17 e v1.0.18) e a página `GET /v1/app/atualizar`: ver a ADR 0065, item 4 da Decisão.

## 6. Impacto
- **Sync e banco:** nenhum. Não há tabela nova; a auditoria usa a do Core.
- **Eventos:** nenhum.
- **Segurança:** o link é segredo de curta duração e não vai a log, auditoria nem aparelho. O binário não leva dado de tenant (premissa (a)).
- **Apps antigos (v1.0.17 e v1.0.18):** sem regressão (ADR 0065, Consequências).
- **Operação pendente:** a lista está na ADR 0065, Consequências.
