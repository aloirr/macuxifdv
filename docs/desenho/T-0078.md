## 2. Carga básica do sync (roteiro)
Ferramenta: `scripts/carga/sync-basico.mjs` (só leitura; login uma vez, N aparelhos virtuais em paralelo fazem a
sincronização completa e R−1 atualizações leves, como o motor do app; sem push, então roda na demo sem gravar nada).

1. Base local com o seed da demo (`pnpm --filter @macuxi/db seed demo`), API local (`pnpm --filter api dev`).
2. `MACUXI_CARGA_EMPRESA`, `MACUXI_CARGA_EMAIL`, `MACUXI_CARGA_SENHA` (vendedor do seed; a senha só por variável),
   `MACUXI_CARGA_APARELHOS=20`, `MACUXI_CARGA_RODADAS=3`; `node scripts/carga/sync-basico.mjs`.
3. Repetir com 50 aparelhos. Critério: nenhum erro; p95 ≤ 2000 ms (`MACUXI_CARGA_P95_MS`); `/v1/saude` sem alerta depois.
4. Na demo (opcional, fora do horário de teste do Alexandre): `MACUXI_CARGA_URL=https://api-demo.macuxifdv.com.br/v1`, 20 aparelhos.
5. A linha JSON de saída vai para o checklist (seção 3, item C1). Execução: agente `testes`.

## 3. Conteúdo proposto para `docs/seguranca/checklist.md`
Legenda: ✅ feito, com prova · 🟡 parcial ou pendente (com o que falta).

- ✅ S1 — Segredos só em `.env` fora do git: `.gitignore` (`.env`, `.env.*`, exceto `.env.example`); VM em `/opt/macuxi/*.env` (chmod 600, `preparar-vm.sh`); CI em secrets do GitHub (`DEMO_SSH_KEY`, environment da demo).

- 🟡 S3 — Varredura automática de segredo no CI (gitleaks ou equivalente): não existe; pede ADR (dependência no CI).

### Banco e isolamento
- ✅ B1 — RLS ligado e forçado com política em toda tabela de domínio e colunas da regra 5: `db/testes/conformidade.test.ts` (S0-023), com as exceções em `db/src/excecoes.ts`. Conferência pedida ao banco-dados (R-20261104-232912).
