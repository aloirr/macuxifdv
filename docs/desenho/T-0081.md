## 1. Objetivo e tela
A entrada **Clientes → "Farol de clientes"** (`modules/core/web/index.ts:34`, hoje `FarolEmBreve`) passa a mostrar a carteira com:
- **Resumo do mês** (período = mês corrente no fuso do tenant; seletor de mês): clientes na carteira, positivados, % de positivação,
  contagem por cor.
- **Por vendedor** (uma linha por vendedor visível): carteira, positivados, % com a cor do vendedor, verdes/amarelos/vermelhos/sem compra.
- **Lista de clientes**: nome, vendedor, última compra, dias sem compra, "positivado no mês" e a cor; ordem padrão = vermelho primeiro,
  depois mais dias sem compra. Clique abre o Cliente 360 que já existe.
- **Filtros**: equipe, vendedor, cor, busca por nome/CNPJ. Sem filtro de curva ABC/segmento (fora, §7).
- **Parâmetros do farol** (painel na mesma tela, só para quem tem `parametro.farol`), no padrão de `inicio-parametros-panel.tsx`.

## 2. Regra proposta — RN-CORE-28 Farol de clientes
1. **Carteira** = clientes vivos e ativos com vínculo de **papel vendedor** vigente em `core.carteira` (promotor não entra). Cliente com
   dois vendedores aparece uma vez em cada um; no resumo do tenant/equipe conta **uma vez**.
2. **Dias sem compra** = hoje (fuso do tenant) − última compra (`max(core.historico_compra.ultima_compra_em)`, mesma fonte e mesma
   função `resumoCompras` do Cliente 360, para os dois números baterem). Sem compra registrada = **"sem compra"** (cinza).
3. **Cor do cliente**: positivado no mês → **verde** sempre. Senão: dias ≤ [`farol.verde_ate_dias` = 30] verde; ≤
   [`farol.amarelo_ate_dias` = 45] amarelo; acima, vermelho. (45 = "cliente sem compra" da Fase M, `idle_days_alert`.)
4. **Positivado no mês** segue a fonte do tenant, nunca somadas: Vendedor efetivo → RN-CORE-20 (listas
   `core.indicador_diario.clientes_positivados_ids` do mês); Vendedor desligado com notas → RN-CORE-27 (`core.nota_erp`).
5. **Cor do vendedor/equipe** pela % de positivação do mês (positivados ÷ carteira): ≥ [`farol.positivacao_verde_pct` = 70] verde
   (70 = `team_coverage_target_pct` da Fase M); ≥ [`farol.positivacao_amarelo_pct` = 50] amarelo; abaixo, vermelho. Carteira vazia = sem cor.
6. **Validação dos parâmetros** (422 `RN-CORE-28`): inteiros; 1 ≤ verde_ate_dias < amarelo_ate_dias ≤ 365;
   0 ≤ positivacao_amarelo_pct < positivacao_verde_pct ≤ 100. Edição auditada (RN-AUD-01), só grava o que mudou.
7. **Quem vê**: supervisor (equipe), gerente (equipes abaixo), analista, assistente e admin (tenant) — RN-CORE-04, mesmo recorte do
   `GET /v1/core/carteira`. Vendedor e promotor não têm a rota. Quem edita os parâmetros: analista e admin.

## 3. Domain (modulo-core, teste antes, citando RN-CORE-28)
`modules/core/domain/farol.ts`, funções puras:
- `corDoCliente({ dias_sem_compra: number | null, positivado_mes: boolean }, p: ParametrosFarol): CorFarol` (`verde|amarelo|vermelho|sem_compra`);
- `corDaPositivacao(positivados, carteira, p): CorFarol | null`;
- `resumirFarol(linhas, p)` → contagens por cor e por vendedor (cliente de dois vendedores conta uma vez no total);
- `parametrosFarolDasLinhas(linhas)` (padrão quando ausente) e `validarParametrosFarol(entrada)`.
Casos mínimos: limites exatos (30 verde, 31 amarelo, 45 amarelo, 46 vermelho), positivado com 90 dias = verde, sem compra, carteira
vazia, cliente duplicado entre vendedores, validação (verde ≥ amarelo recusa).
