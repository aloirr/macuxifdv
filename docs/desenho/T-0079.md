# Desenho T-0079 — App percebe a base recriada (geração da base no sync)

Decisão: **ADR 0021** (`docs/decisoes/0021-geracao-da-base-no-sync.md`). Origem: bug "pedido fantasma 000011"
(R-20261104-163228), diagnóstico R-20261104-195513 (banco-dados), resposta R-20261104-202218.

## Contrato (aditivo, sem versão nova)
- `GET /v1/sync/pull` → `{ itens, proximo_cursor, versao_escopo?, horizonte, geracao_base? }`.
- `GET /v1/sync/novidades` → `{ entidades, cursor, horizonte, modulos_mudaram, modulos?, geracao_base? }`.
- Ausente quando o banco não tem a coluna (antes da 0022). O app antigo ignora (pull sem schema estrito; novidades com
  `z.object`, que descarta campo desconhecido).
- **Não** vai no `/v1/me/modulos` nem no login: o APK lê esses com `.strict()` (ADR 0021 §3).

## Regra no aparelho
`decidirGeracao(guardada, recebida)` → `sem_marcador` | `adotar` | `igual` | `trocou`. Guardada em `sync:geracao_base`.

Troca (`trocou`), na sincronização completa ou leve:
1. aceitos ainda sobrepostos → fila (`pendente`), ordem de criação;
2. `motor.enviar()` (o recusado fica `falhou`, visível);
3. apaga linhas, cursores, `sync:escopo:*`, `sync:ressinc:*`, `sync:carga`, `sync:novidades` (numa transação quando o adaptador
   sabe). Ficam: `sync:fila`, `sync:arquivos`, `sync:modulos`, `sync:parametros`, `sync:limpeza_pendente`, `sync:sincronizado_em`;
4. `aoTrocarGeracao(ctx)` de cada etapa (cache do módulo em `mod:<m>:`);
5. grava a geração nova e refaz a passada completa (uma vez; se mudar de novo: erro `MENSAGEM_GERACAO_INSTAVEL`).

Idempotente: a geração só é gravada no fim; se o app cair, a próxima sincronização repete os passos.

## Impacto em sync e dados
- Uma consulta por PK (`plataforma.tenant`) por página do pull e por novidades; se a coluna não existe (42703), a API para
  de tentar por 60 s.
- Aparelho que já tem o fantasma antes da primeira geração adota a primeira sem limpar (ADR 0021, consequências).
