# Desenho T-0060 — Cadastro mínimo do cliente (RN-CORE-16/17, RN-VEN-13, RN-INT-14)

> 2026-11-02 · engenheiro-software · status: **proposta para o gerente** (pedido R-20261102-094239) · origem: decisão do
> Alexandre R-20261102-092329 · schema: `db/migrations/0013_catalogo_vendedor_prevenda.up.sql` (banco-dados, em andamento)

## 1. Decisões
1. **A regra mora no domain do Core** (`modules/core/domain/cadastro.ts`): `cadastroCompleto(cliente, campos)` pura. A validação
   de CNPJ/CPF é utilitário transversal em **`@macuxi/comum/documento`** (feito nesta rodada: `cnpjValido`, `cpfValido`,
   `tipoDocumento`, `completarCnpj`/`completarCpf` para seeds, `formatarDocumento`; 6 testes RN-CORE-16).
2. **O Hub não decide o cadastro**: ele só não recusa (o `ClientePayload` já tem `documento` opcional) e **pergunta ao Core**
   pela consulta nova `core.cadastro_cliente@1` (ADR 0012) dentro da aplicação do lote (A7, mesma transação), para gravar o
   **aviso de linha** `cadastro_incompleto` (RN-INT-14) que o monitor mostra. Assim a lista do tenant e a regra ficam num lugar só
   (o Core), e o Hub não lê parâmetro de outro módulo.
3. **O Core grava o resultado** ao aplicar `integracao.cliente.atualizado@1` e na edição pelo BKO: colunas
   `cadastro_incompleto` e `cadastro_campos_faltantes` (0013). A sincronização (pull) leva as duas colunas; o aparelho não recalcula.
4. **Observações: a linha automática é montada na exibição, nunca gravada** (como a 0013 já prevê): `observacao` guarda só o
   texto do ERP; `observacaoComCadastro(observacao, campos_faltantes)` fica no domain do Core e é usada pelo app e pelo BKO do
   Core (as telas de Cliente 360 são do Core). Some sozinha quando a lista fica vazia; o texto do ERP nunca é alterado.
5. **Parâmetro**: `plataforma.parametro` módulo `core`, chave **`cliente.campos_obrigatorios`** (nome do doc 03:
   `cliente_campos_obrigatorios`). Valor = lista de códigos de `CAMPOS_CADASTRO_CLIENTE`. Ausente ou inválido = padrão. O domain
   **sempre** inclui `documento` (o tenant não pode tirar o CNPJ/CPF) e `razao_social`.
6. **RN-VEN-13 no servidor**: o Vendedor lê `cadastro_incompleto`/`cadastro_campos_faltantes` pela `core.cadastro_resumo@1`
   (campos novos opcionais na saída) e recusa enviar (422 `RN-VEN-13`, mensagem com os campos) — orçamento continua permitido.

## 2. Contratos (o dono escreve; texto exato abaixo)

### 2.1 Core — `modules/core/contracts` (modulo-core)
```ts
// cadastro.ts (novo)
export const CAMPOS_CADASTRO_CLIENTE = [
  'razao_social', 'documento', 'inscricao_estadual', 'logradouro', 'numero', 'bairro', 'cidade', 'uf', 'cep',
  // extras que o tenant pode exigir
  'nome_fantasia', 'telefone', 'email', 'complemento', 'geolocalizacao',

export const CampoCadastroCliente = z.enum(CAMPOS_CADASTRO_CLIENTE);
export type CampoCadastroCliente = z.infer<typeof CampoCadastroCliente>;
/** Padrão do doc 03 (RN-CORE-16). `inscricao_estadual` só vale para CNPJ ("ISENTO" conta como preenchida). */
export const CAMPOS_CADASTRO_PADRAO: readonly CampoCadastroCliente[] =
  ['razao_social', 'documento', 'inscricao_estadual', 'logradouro', 'numero', 'bairro', 'cidade', 'uf', 'cep'];
/** plataforma.parametro (core, 'cliente.campos_obrigatorios'); sem `documento` o domain acrescenta. */
export const PARAMETRO_CAMPOS_OBRIGATORIOS = 'cliente.campos_obrigatorios';
export const ParametroCamposObrigatorios = z.array(CampoCadastroCliente).min(1).max(CAMPOS_CADASTRO_CLIENTE.length);
```
- `ClienteSyncSchema` (sync.ts), campos **opcionais** (APK antigo e linhas antigas continuam válidos):
  `inscricao_estadual: z.string().nullable().optional()`, `observacao: z.string().nullable().optional()`,
  `cadastro_incompleto: z.boolean().optional()`, `cadastro_campos_faltantes: z.array(z.string()).optional()`
  (`z.string()` e não o enum: o aparelho antigo não pode reprovar a linha quando o tenant usar um campo novo).
- `Cliente360Schema` e o resumo da carteira: os mesmos 4 campos, opcionais.
- **`core.cliente.atualizado@1`** (eventos.ts): `cadastro_incompleto: z.boolean().optional()`,
  `cadastro_campos_faltantes: z.array(z.string()).optional()` — aditivo, sem nova versão (o schema não é `.strict()`).
- **`core.cadastro_resumo@1`** (consultas.ts), saída `clientes[]` ganha opcionais: `inscricao_estadual`, `cep`,
  `cadastro_incompleto: z.boolean().optional()`, `cadastro_campos_faltantes: z.array(z.string()).optional()`.
- **Consulta nova `core.cadastro_cliente@1`** (para o Hub, RN-INT-14):
```ts
export const CadastroClienteEntradaSchema = z.object({
  clientes: z.array(z.object({
    chave: z.string().max(200),               // o external_id do lote (o Hub casa a resposta)
    razao_social: z.string().nullable(), nome_fantasia: z.string().nullable(), documento: z.string().nullable(),
    inscricao_estadual: z.string().nullable(), telefone: z.string().nullable(), email: z.string().nullable(),
    logradouro: z.string().nullable(), numero: z.string().nullable(), complemento: z.string().nullable(),
    bairro: z.string().nullable(), cidade: z.string().nullable(), uf: z.string().nullable(), cep: z.string().nullable(),
    latitude: z.number().nullable(), longitude: z.number().nullable(),
  })).max(500),
}).strict();
export const CadastroClienteSaidaSchema = z.object({
  resultados: z.array(z.object({ chave: z.string(), completo: z.boolean(), campos_faltantes: z.array(z.string()) })),
});
export const CONSULTA_CADASTRO_CLIENTE = definirConsulta({ nome: 'core.cadastro_cliente@1', entrada: CadastroClienteEntradaSchema, saida: CadastroClienteSaidaSchema });
```
  Sem dado do cliente na resposta (só a chave e os nomes dos campos); a consulta é pura (lê só o parâmetro do tenant).

### 2.2 Domain do Core (modulo-core; testes antes, citando RN-CORE-16/17)
```ts
export function camposExigidos(parametro: unknown): CampoCadastroCliente[]        // inválido = padrão; sempre + documento, razao_social
export function cadastroCompleto(c: DadosCadastro, exigidos: readonly CampoCadastroCliente[]):
  { completo: boolean; campos_faltantes: CampoCadastroCliente[] }                  // ordem de CAMPOS_CADASTRO_CLIENTE
export function observacaoComCadastro(observacao: string | null, faltantes: readonly string[]): string | null
// "Cadastro incompleto: falta CNPJ/CPF, CEP. Pedido só como orçamento até o cadastro ser completado no ERP." + "\n" + observacao
export const ROTULO_CAMPO_CADASTRO: Record<CampoCadastroCliente, string>          // 'documento' → 'CNPJ/CPF', 'cep' → 'CEP' …
```
Regras do `cadastroCompleto`: texto vazio/só espaço = ausente; `documento` com DV inválido = ausente (`tipoDocumento`);
`inscricao_estadual` só é exigida quando `tipoDocumento === 'cnpj'` (CPF nunca falta IE; "ISENTO", sem diferenciar
maiúsculas, conta como preenchida); `uf` = 2 letras de UF brasileira; `cep` = 8 dígitos; `geolocalizacao` = latitude e longitude.

### 2.3 Integração (modulo-integracao)
- `ClientePayload` (contracts/entidades.ts), opcionais: `inscricao_estadual: TextoOpcional(20)`, `observacao: TextoOpcional(1000)`.

- Manifesto da Integração: `usaConsultas: ['core.cadastro_cliente@1']`; do Core: `ofereceConsultas` com a nova.

  normalmente. Nunca erro cru (T-0059).
