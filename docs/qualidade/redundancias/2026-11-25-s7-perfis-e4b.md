Escopo: commit `28386327c` (modulo-core, ADR 0073 E4b, 1 commit sobre o merge 0108 + #782): `modules/core/api/perfis-v2.ts`, `domain/perfis-cargo.ts`, `contracts/perfis.ts`, testes `perfis-v2.test.ts`, `perfis-v2.db.test.ts` e `perfis-cargo.test.ts`.

## RD-3716 — `mesmosAlvosV2` copia `mesmosAlvos` do mesmo domain (código, média)
- `domain/perfis-cargo.ts:198` reescreve `mesmosAlvos` de `domain/perfis.ts:53` (mesmo corpo: ordena, junta, compara).
- Correção: apagar `mesmosAlvosV2`; `import { mesmosAlvos } from './perfis';` e usar `mesmosAlvos(antes[c]!.alvos, depois[c]!.alvos)` em `diffConcessoes`.

## RD-3717 — linha do banco → `ValorPermissao` montada 4 vezes (código, média)
- `{ ...(x.nivel ? { nivel: x.nivel } : {}), ...(x.alvos ? { alvos: [...x.alvos] } : {}) }` em `perfis-v2.ts:117` (`carregar`), `:133` (`carregarModelos`), `:205` (`gravarConcessoes`) e `perfis-cargo.ts:194` (`permissoesDoCorpo`).
- Correção: em `perfis-cargo.ts`, `export const valorDaConcessao = (nivel?: ValorPermissao['nivel'] | null, alvos?: readonly string[] | null): ValorPermissao => ({ ...(nivel ? { nivel } : {}), ...(alvos ? { alvos: [...alvos] } : {}) });`; `permissoesDoCorpo` usa `r[p.chave] = valorDaConcessao(p.nivel, p.alvos)` e as três linhas da API usam `valorDaConcessao(c.nivel, c.alvos)` / `valorDaConcessao(l.nivel, l.alvos)`.

## RD-3718 — regra do nome repetido (RN-CORE-35) inline duas vezes na API (código, média)
- `perfis-v2.ts:296` (POST) e `:355` (PUT): `e.linhas.some((l) => ... l.ativo && l.nome.toLowerCase() === nome.toLowerCase())` + o mesmo `throw`. Regra de negócio fora do domain, copiada.
- Correção: em `perfis-cargo.ts`, `export function nomeJaUsado(perfis: readonly { id: string; nome: string; ativo: boolean }[], nome: string, ignorarId?: string): boolean { const n = nome.toLowerCase(); return perfis.some((p) => p.id !== ignorarId && p.ativo && p.nome.toLowerCase() === n); }` (RN-CORE-35, com teste); na API, `const repetido = () => new ErroRegraNegocio(CODIGO_REPETIDO, MENSAGEM_PERFIL_REPETIDO, { regra: 'RN-CORE-35' });`, POST `if (nomeJaUsado(e.linhas, nome)) throw repetido();`, PUT `if (ativo && nomeJaUsado(e.linhas, nome, linha.id)) throw repetido();`.

## RD-3719 — licença do módulo (RN-CORE-02) escrita 3 vezes (código, baixa)
- `m === 'core' || licencas.has(m)` em `perfis-cargo.ts:69` (`montarCatalogoPorArea`), `:168` (`montarDetalheV2`) e `perfis-v2.ts:221` (`soLicenciadas`).
- Correção: em `perfis-cargo.ts`, `export const moduloLicenciado = (modulo: string, licencas: ReadonlySet<ModuloId>) => modulo === 'core' || licencas.has(modulo as ModuloId);` e as três usam `moduloLicenciado(...)` (em `soLicenciadas`: `return !m || moduloLicenciado(m, licencas);`).

## Conferido sem achado
- Regra do SDK: travas, teto, senha e último admin vêm de `validarAcessoPeloCargo` (`conferir`), `travaDaChavePeloCargo`, `tetoDeEscopoDoCargo`, `protegidoDaSenha` e `temGestaoDoAcesso`; `ondeEntraPeloCargo` reusa `resolverPerfilPeloCargo` + `CHAVE_ACESSO`; `violacoesNovas` só filtra o que já existia. `PERFIL_PADRAO_FIXO` (fábrica) não existe no SDK: é regra da transição da API.
- Rotas antigas (`perfis.ts`): `FORA_DA_TELA`, `LUGARES` e o nome repetido também estão lá, mas `perfis.ts` sai inteiro na E6 (convivência).
- `gravarConcessoes` relê `perfil_concessao` em vez de usar o que `carregar` já leu: necessário, o espelho da 0107 refaz as concessões ao inserir o perfil ou trocar o cargo.
- Testes: `perfis-cargo.test.ts` confere o mapeamento do detalhe (cadeado, teto, licença, alvos) sem repetir a matriz do SDK; `perfis-v2.db.test.ts` cobre o 422/409 vindo do Postgres; `perfis-v2.test.ts` cobre ação, status e contrato. Sem caso repetido.
