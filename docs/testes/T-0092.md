# T-0092 — matriz de testes (Hub: `GET /integracao/v1/openapi.json` público)

Escopo do agente testes: cruzar os critérios 1 a 4 com os testes que já existem (engenheiro-software, SDK e
modulo-integracao) e escrever teste de integração só onde faltava cobertura. Decisão de produto: R-20261106-073936 (rota
pública, sem token, só a especificação); ADR 0030 (exceção ao item 4 da ADR 0006 para documento público de módulo).
Sem Docker: todos os testes abaixo rodam sem banco (local e CI).

## Testes existentes (dos donos)

**Lacuna encontrada:** nenhum teste montava a API com o módulo Integração **real** (a rota que o módulo declara, o
documento de verdade, o limite de 60 e não o de fixture), nem provava que a rota autenticada `/v1/integracao/openapi`
(T-0087) saiu. Coberta por `tests/integracao/api/openapi-publico-t0092.test.ts` (novo, sem banco).

| Id | Gravidade | Achado | Dono | Recado |

| T92-D3 | 🟢 | `rota-publica-documento.test.ts` › "convive com as rotas de Conector" faz `POST /integracao/v1/sinal-de-vida`, que não é rota do Hub (a real é `/sinal`): o `>= 400` passa com 404 e não prova que a rota do Conector continua pedindo a chave. ## Manual (ambiente de demo, depois do deploy)

1. `curl -i https://<demo>/integracao/v1/openapi.json` sem cabeçalho → 200, `Cache-Control: public, max-age=3600`, `ETag`.
2. `curl -i -H 'If-None-Match: <etag>' …` → 304 sem corpo.
3. Atrás do túnel (`MACUXI_TRUST_PROXY`): 61 chamadas seguidas do mesmo aparelho → a 61ª 429 com `Retry-After`; de outra rede segue 200 (confere que o IP é o do cliente, não o do túnel).
4. Importar a URL no Postman/Swagger Editor: abre sem erro e lista as 7 rotas.
