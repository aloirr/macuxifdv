# T-0091 — matriz de testes (super-admin no papel `macuxi_portal`)

Escopo do agente testes: o teste de segurança do critério 3 e a conformidade da 0038 (R-20261106-234527-banco-dados,
R-20261106-231444 e R-20261106-234618-engenheiro-software; desenho `docs/desenho/T-0091.md` §6; RN-CORE-31).
Testes de banco rodam só no CI (sem Docker no PC). No PC: lint, `typecheck:tests` e os arquivos carregando (pulam sem banco).
Os casos que precisam da senha de um papel (`urlWorker`/`urlPortal` nulos) pulam com o motivo no título; no CI o Postgres é
local e os dois papéis têm login (senhas locais do `@macuxi/db`).

## Banco — conformidade (tests/integracao/banco/conformidade.test.ts)

| Cenário | Caso | Estado |
|---|---|---|
| As 20 `sa_*` saem da lista do `macuxi_app` (`DEFINER_REVISADAS`, igualdade exata: se o app voltar a executar alguma, reprova) | "funções SECURITY DEFINER executáveis pelo papel" | CI |
| Worker segue sem nenhuma `sa_*` | `DEFINER_REVISADAS_WORKER` sem mudança | CI |
| SECURITY DEFINER do `macuxi_portal` = exatamente as 20 `sa_*` (assinatura exata), search_path fixo, sem PUBLIC | `DEFINER_REVISADAS_PORTAL` (novo) | CI |
| Pelo catálogo (`pg_proc`, não lista fixa): toda `plataforma.sa_*` tem EXECUTE (ACL) só para o dono e o `macuxi_portal`; a interna `sa_registrar_auditoria` só para o dono; `has_function_privilege` confirma app/worker = não, portal = sim; catálogo e lista revisada do mesmo tamanho | novo | CI |
| Portal: sem SUPERUSER/BYPASSRLS/CREATEROLE/CREATEDB/REPLICATION | novo | CI |
| Portal não é membro de papel nenhum (nem `macuxi_manutencao`, nem `macuxi_app`) | novo | CI |
| Portal não é dono de schema, relação, função ou tipo | novo | CI |
| Portal sem grant de tabela/view/sequência/coluna (`relacl`/`attacl`, `role_table_grants` = 0) e sem privilégio efetivo em tabela nenhuma | novo | CI |
| Portal: USAGE só no schema `plataforma`; nenhum CREATE (nem no `public`) | novo | CI |
| `diagnosticarPapelApp(admin, 'macuxi_portal')` aprova | novo | CI |

## API em dois pools (tests/integracao/api/portal-dois-pools-t0091.test.ts; apoio `tests/integracao/apoio/api.ts`)

O apoio sobe a API como em produção: `bancoPortal: criarBancoPortal(pool do urlPortal, max 2)`; `semPortal: true` sobe sem
ele; `espiarSql: true` guarda o texto (nunca os parâmetros) de cada comando de cada pool.

| Critério | Cenário | Caso |
|---|---|---|
| 2 | `verificar()` recusa `macuxi_app` e o admin no banco do portal; aceita o `macuxi_portal`; `comTenant` do portal lança | DP-01 |
| 2/3 | Primeiro acesso, TOTP, sessão, listar e criar empresa: toda `sa_*` saiu do pool do portal, nenhuma do pool do app; o portal nunca põe tenant no contexto nem toca tabela de módulo | DP-02 |
| 2 | Rota de módulo com `superAdmin: 'aceita'` (`GET /v1/integracao/conectores`): sessão, tenant ativo e auditoria no portal; licença e dado do tenant no app (com `app.tenant_id`) | DP-03 |
| 2 | Login, `/v1/me/modulos`, `/v1/core/usuarios` e 401 sem token: nenhum comando no pool do portal | DP-04 |
| 3 | Cada sessão aberta tem a sua `sa.sessao.aberta`; `sa.primeiro_acesso`, `sa.totp.confirmado`, `sa.tenant.provisionar`, `sa.requisicao` gravadas; como `macuxi_portal`, ler/inserir/alterar/apagar a auditoria = 42501 | DP-05 |
| 2 | Sem o pool do portal: as 8 rotas `plataforma/auth/*` = 503 `PORTAL_INDISPONIVEL` | DP-06a |
| 2 | Sem o pool: `GET/POST /v1/plataforma/empresas` (com e sem token) e token de plataforma na rota do Hub = 503; nenhuma empresa criada | DP-06b |
| 2 | Sem o pool: tenants seguem (login, módulos, Core = 200; sem token e token inválido = 401; token de tenant na rota do Hub = 403 `MODULO_INATIVO`, não 503) | DP-06c |

## Auditoria com dois pools (tests/integracao/api/super-admin-t0087.test.ts)

O arquivo inteiro (SA-01..11) passa a rodar com o pool do portal (apoio). Novo **SA-10d**: as ≥ 3 sessões abertas no arquivo têm,
uma a uma, a linha `sa.sessao.aberta`; o `macuxi_portal` não lê, não altera e não apaga a auditoria (42501).
