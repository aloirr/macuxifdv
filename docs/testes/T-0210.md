# T-0210 — Vendas do mês segue as RN (1 A): matriz de cenários

Regras RN-CORE-20 (positivado = pedido aprovado emitido no período) e RN-CORE-21 (realizado pelo tipo da meta; faturamento = valor faturado na data do faturamento, líquido de cancelamentos e devoluções).
Base: `origin/main` 1aeace4 (v1.0.43), base demo (`carregarDemo`) × `createApp` real × Postgres local, em 28/11/2026 (Manaus).

Arquivo: `tests/integracao/demo/vendas-mes-rn-t0210.test.ts`. Oráculo escrito no teste a partir do texto da RN, com os fatos lidos do banco (`vendedor.pedido`, `vendedor.pedido_faturamento`, `vendedor.pedido_devolucao`, `core.meta.tipo`). Telas: ficha `GET /v1/gestor/equipe/:id` (`painel.mes`), atingimento da equipe `GET /v1/gestor/equipe` (`resumo.atingimento_pct`), Ranking mensal `GET /v1/gestor/ranking` (`vendas_cents`, `positivados`) e BKO Indicadores `GET /v1/core/indicadores`.

Convenção: `it.fails` = defeito aberto (vira `it` no commit da correção).

## Cenários

| Cenário | `core` `metas.base_apuracao` | `gestor` `base_apuracao` | `core.meta.tipo` (venda) |
|---|---|---|---|
| S0 (demo como está) | aprovado | ausente (padrão aprovado) | pedido |
| S1 | faturado | ausente | pedido |
| S2 | aprovado | ausente | faturamento |
| S3 | faturado | ausente | faturamento |
| S4 | aprovado | faturado | pedido |
| S5 | aprovado | faturado | faturamento |

O gestor só lê os parâmetros do próprio módulo (`ctx.parametros()` do módulo `gestor`): a ponte para `metas.base_apuracao` em `modules/gestor/domain/parametros.ts` não recebe a chave do core pela API (S1 = S0).
