# T-0093 — matriz de testes (portal `config.` só com e-mail e senha, escolha de empresa, RN-CORE-32)

Escopo do agente testes: fatia T do desenho `docs/desenho/T-0093.md` §11 (pedidos R-20261107-145433-engenheiro-software e
R-20261107-165217-banco-dados; ADR 0031; regras RN-CORE-31, RN-CORE-32, RN-CORE-33, RN-CORE-34, RN-AUD-01).
Testes de banco e de API com Postgres rodam só no CI (`stack-isolado.yml`, sem Docker no PC); no PC: lint, `typecheck:tests`,
os arquivos carregando (pulam sem banco) e o autoteste do script da demo (sem rede).
Base de dados dos casos de API: banco efêmero do arquivo com a fixture **dois-tenants** (A "Distribuidora Alfa", B "Comercial
Beta"); o mesmo e-mail é montado em A e B pela conexão de administração (a fixture só repete o e-mail do vendedor) e o
super-admin nasce como no deploy (`plataforma.criar_super_admin`).

Arquivos:
- `tests/integracao/api/portal-email-senha-t0093.test.ts` (novo, PE-01..07) — critérios 1 a 6;
- `tests/integracao/api/super-admin-t0087.test.ts` (reescrito para o fluxo novo, SA-01..11) — critérios 1, 4, 6 e 7;
- `tests/integracao/api/portal-dois-pools-t0091.test.ts` (reescrito, DP-01..06) — critério 6 (só o `macuxi_portal`);
- `tests/integracao/banco/conformidade.test.ts` e `tests/integracao/banco/papel-portal-t0091.test.ts` (lista nova da 0039);
- `tests/scripts/portal-demo-no-ar.mjs` + `tests/integracao/demo/portal-demo-no-ar.test.ts` (autoteste) — critério 8;
- apoio `tests/integracao/apoio/portal.ts` (criar super-admin/usuário, login, token forjado, auditoria).

## Roteiro manual (critério 8, depois do deploy da demo)
1. Gerente confirma: workflow "demo — super-admin" rodado com o e-mail do dono do produto e o secret `DEMO_SUPERADMIN_SENHA`.
2. No PC: `node tests/scripts/portal-demo-no-ar.mjs` → 4 OK (sem credencial).
3. Com a credencial (só no terminal, nunca em arquivo): `MACUXI_DEMO_PORTAL_EMAIL=... MACUXI_DEMO_PORTAL_SENHA=... node
   tests/scripts/portal-demo-no-ar.mjs` → `OK acesso login 200: super-admin; vê N empresa(s); sessão encerrada (204)`.
4. No navegador, `https://config-demo.macuxifdv.com.br/`: a tela tem só E-mail e Senha (sem "Primeiro acesso", código ou QR);
   senha errada mostra "E-mail ou senha incorretos."; a certa abre a lista de empresas (super-admin).
5. Escolha de empresa: com um e-mail admin em 2 empresas da demo (criar pelo passo Empresa com o mesmo e-mail de admin
   inicial em duas empresas), entrar mostra "Escolha a empresa" com os dois nomes; escolher abre a empresa; "Trocar de
   empresa" volta à lista.
6. Cinco senhas erradas seguidas com o mesmo e-mail → a 5ª já diz "Acesso bloqueado… 15 minutos" (inclusive com e-mail que não existe).

## Pendências e premissas
- Os casos de CI dependem das fatias B, C, S e W no mesmo lote (a 0039 apaga as funções antigas). Escritos contra o desenho e
  o código do working tree de 07/11; o resultado do CI é o critério.
- `'exige'` com admin do cliente: sem rota real nos módulos; fica nos testes da API (fatia S).
- Precedência e tempo de conferência (mesmo número de conferências para e-mail inexistente): no Core (fatia C, bancos falsos).
