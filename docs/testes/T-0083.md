## Premissas
- O tenant N recebe o mesmo e-mail de admin que A e a demo: é o pior caso de login entre tenants e o que mais acontece de verdade (o e-mail do dono da distribuidora já é usado na demo).
- Um id "alheio" é qualquer `id` de tabela com `tenant_id` de outro tenant, mais os ids dos tenants. Os ids padrão (motivos, parâmetros) são derivados do tenant (`idMotivoPadrao`), então não coincidem entre tenants.

## Teste manual (VM da demo, depois do CI verde)
1. `docker compose run --rm -e MACUXI_PG_ADMIN_SENHA -e MACUXI_TENANT_ADMIN_SENHA api pnpm tenant criar --codigo piloto-x --nome "Piloto X" --modulos core,catalogo,vendedor --admin-email <e-mail> --admin-nome "<nome>" --confirmar piloto-x`.
2. Conferir que a saída mostra o e-mail mascarado e `resultado: criado`. Rodar de novo e conferir `sem_mudanca`.
3. No BKO, entrar com o código `piloto-x`. O menu mostra só Core, Catálogo e Vendedor; Clientes, Usuários e Auditoria vêm vazios, exceto o próprio admin e a linha do provisionamento.
4. Entrar com o código `demo` no mesmo navegador: nada de `piloto-x` aparece.
