## Cenários de regressão que a catraca cobre
Não são casos novos: o teste reprova quando algo sai do padrão.
- Módulo publica evento sem definição exportada → "todo evento publicado…" fica vermelho.
- `contracts` exporta definição de evento alheio (o caso antigo do `vendedor/contracts/pre-venda.ts`) → idem.
- Consumidor volta a usar cópia ou o schema do dono sem `eventoTolerante` → "todo consumidor lê…" fica vermelho. Fica
  fora o Gestor com `z.unknown()`, que tem cobertura própria no `gestor/contracts/index.test.ts`.
- Consumidor de evento renomeado ou com versão nova sem o dono publicar → "todo evento consumido existe…".

Uma mudança incompatível com o mesmo `@N` não é pega pela catraca. Ela é pega pelos testes de congelamento do dono:
o do promotor (T-0040, "formato congelado dos payloads @1") e os exemplos dos outros. Só o Promotor congela tipo e
chaves. Para os demais, sugiro ao engenheiro-software a mesma proteção quando houver um consumidor externo.
