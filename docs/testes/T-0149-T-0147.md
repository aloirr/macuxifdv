## Defeitos
- **D-1 (modulo-core) — CORRIGIDO em 10/11 (RD-0080; R-20261110-123325):** `podeAbrirFoto`/`perfisDeLeitura` olham `fachada`, o pull só leva o `arquivo_id` da fachada e `fachadaDoPdv(tipos, fotos)` substituiu `podeVerFotoDoPdv`. Histórico do achado: `modules/core/domain/fotos-pdv.ts`, `podeAbrirFoto`/`perfisDeLeitura` só olham `sensivel`; o pull (`modules/core/api/sync.ts`, `cliente_foto`) só anula o `arquivo_id` do sensível. Um tipo como "Interior da loja" (não sensível, não fachada) abre para o vendedor. A RN-CORE-38 e o critério 4 da T-0147 dizem: "o vendedor vê só a fachada; dos outros tipos, vê só que existem e não os reabre". O desenho (`docs/desenho/T-0147.md`, tabela do domínio) diz "não sensível → regra da carteira de hoje". Reproduzir: admin cria o tipo "Interior da loja" sem marcar sensível; o vendedor envia a foto; no pull seguinte o `arquivo_id` vem preenchido e o resumo da API devolve o `arquivo_id` ao vendedor.

## Observações
- O pull de `cliente_foto` é igual para todos os perfis: o supervisor no Gestão também recebe `arquivo_id` nulo nos sensíveis e só abre pela API (`GET /v1/core/clientes/:id/fotos`). Fica com o modulo-core/designer-ux se o Gestão tiver de abrir CNH.
